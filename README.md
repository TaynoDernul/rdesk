# rdesk

Удалённый рабочий стол для личного использования на Windows: подключение по ID из любой сети, аппаратный H.264 или H.265, до 60 FPS, звук, файлы в обе стороны, сквозное шифрование. Один файл `rdesk.exe` для обоих компьютеров, установка не нужна. Белый IP, проброс портов и VPN не требуются. Проверено на Windows 11 и 10.

## Как пользоваться

Скачайте `rdesk.exe` со страницы [последнего выпуска](https://github.com/TaynoDernul/rdesk/releases/latest), скопируйте на оба ПК и откройте двойным щелчком.

**Один раз для каждой пары компьютеров:**

1. На удалённом ПК введите PIN (не меньше 6 символов) и нажмите **«Задать PIN»**.
2. Там же нажмите **«Копировать»** рядом с «ID этого ПК» и перешлите ID себе любым способом. ID не секретен: без кода и PIN он доступа не даёт. Если оба ПК в одной локальной сети, ID можно не пересылать: нажмите **«Найти в локальной сети»** и выберите ПК из списка.
3. На удалённом ПК нажмите **«Добавить устройство»**. Появится код из 8 цифр, он действует 2 минуты.
4. На своём ПК в разделе **«Добавить компьютер»** вставьте ID, придумайте название, введите код и нажмите **«Добавить»**.

**Для подключения:**

1. На удалённом ПК нажмите **«Разрешить подключения»** или включите автозапуск.
2. На своём ПК выберите компьютер, введите его PIN и нажмите **«Подключиться»**.

В заголовке окна сеанса видно, как идёт связь: «напрямую» или «через ретранслятор», а также задержка, FPS и битрейт.

Обе программы должны быть одной версии.

Чтобы удалённый ПК принимал подключения без вашего участия, включите на нём **«Запускать при входе в Windows и принимать подключения»**. При закрытии окна с включёнными подключениями программа остаётся в трее.

## В сеансе

В левом верхнем углу окна сеанса есть вкладка **«☰ Меню сеанса»**. Она видна и в полноэкранном режиме.

| Действие | Как |
|---|---|
| Полный экран | Меню или `Ctrl+Alt+Shift+F` |
| Другой монитор | Меню «Монитор» или `Ctrl+Alt+Shift+M` |
| Качество | Меню «Качество»: меняется сразу, без переподключения |
| Звук | Идёт с удалённого ПК по умолчанию, выключается в меню или переключателем в главном окне |
| Только просмотр | Меню: мышь и клавиатура остаются на вашем ПК |
| Отправить файлы или папку | Перетащите в окно или выберите в меню. Файлы попадут в `Загрузки\rdesk` на удалённом ПК |
| Скачать с удалённого ПК | Меню «Скачать файлы…»: окно выбора откроется на экране удалённого ПК. Файлы попадут в `Загрузки\rdesk` на вашем ПК |
| Буфер обмена | Включается переключателем перед подключением. Переносит текст, картинки и скопированные файлы (до 200 МБ) |
| Чат | Меню «Чат…». На удалённом ПК кнопка «Чат» на красном баннере |
| Выйти | Меню, `Ctrl+Alt+Shift+Q` или закрыть окно |

Ход передачи файлов виден в заголовке окна.

## Как идёт соединение

1. По ID программа находит удалённый ПК через сервис обнаружения компании [n0](https://n0.computer), которая разрабатывает библиотеку [iroh](https://iroh.computer). В одной локальной сети ПК находят друг друга и сами, через mDNS, даже без интернета.
2. Сначала пакеты идут через ретранслятор, параллельно пробивается NAT, и при успехе соединение само переходит на прямой путь. За большинством домашних роутеров это удаётся.
3. Если прямого пути нет (например, оба ПК за CGNAT мобильного оператора), сеанс продолжается через ретранслятор. Качество тогда подстраивается под канал: битрейт и частота кадров снижаются, чтобы не росла задержка.

Ретрансляторы и сервис обнаружения видят IP-адреса и ID устройств, но не содержимое: соединение зашифровано сквозным образом. Серверы n0 бесплатны и работают без гарантий. Если у вас есть VPS, можно поднять свой ретранслятор (см. ниже).

**Проверка связи:** в командной строке выполните `rdesk.exe net-check`. Программа проверит доступ к ретранслятору и пробное подключение по ID.

## Свой ретранслятор на VPS

Через свой сервер связь не зависит от загрузки бесплатных серверов n0, а если сервер близко, задержка ниже. Подойдёт любой VPS с Linux, публичным IP и доменным именем (можно бесплатный поддомен, например от DuckDNS).

1. Откройте на сервере порты **80/tcp** и **443/tcp**, а для пробивки NAT ещё **7842/udp**.
2. Скачайте `iroh-relay` версии **1.4** для Linux со страницы выпусков [n0-computer/iroh](https://github.com/n0-computer/iroh/releases) или соберите его: `cargo install iroh-relay --version 1.4.1 --features server`.
3. Создайте файл `relay.toml` (вместо `relay.example.com` укажите свой домен, вместо токена — длинную случайную строку):

   ```toml
   enable_quic_addr_discovery = true
   # Иначе статистика сервера будет открыта всем на порту 9090.
   enable_metrics = false

   [tls]
   cert_mode = "LetsEncrypt"
   hostname = ["relay.example.com"]
   contact = "you@example.com"

   [access]
   shared_token = ["замените-на-длинную-случайную-строку"]
   ```

   Токен не пускает на ваш сервер чужих. Сертификат Let's Encrypt сервер получит сам.
4. Запустите сервер:

   ```bash
   sudo ./iroh-relay --config-path relay.toml
   ```

   Чтобы он работал постоянно, оформите его как службу systemd.
5. В rdesk на **обоих** ПК откройте **«Настройки»**, укажите адрес вида `https://relay.example.com/?token=ваш-токен`, нажмите **«Сохранить ретранслятор»** и перезапустите rdesk.

Проверить работу можно так: в заголовке окна сеанса будет «через ретранслятор» (если прямой путь не нашёлся), а в журнале сервера появятся подключения. Поиск ПК по ID по-прежнему идёт через сервис обнаружения n0: он хранит только адрес ретранслятора и IP, но не содержимое.

## Пробуждение по сети

После первого сеанса rdesk запоминает адреса сетевых карт удалённого ПК, и рядом с кнопкой «Подключиться» появляется **«Разбудить»**. Сигнал Wake-on-LAN доходит только внутри одной локальной сети и работает, если пробуждение включено в BIOS и в свойствах сетевой карты. Обычно надёжнее всего по проводу.

## Внешний вид и настройки

- **Тема** выбирается в правом верхнем углу окна: «как в Windows», светлая или тёмная. Заголовки окна программы и окна сеанса тоже следуют теме, а цвет кнопок берётся из акцентного цвета Windows.
- **Журнал подключений** показывает, кто и когда подключался к этому ПК и куда подключались отсюда.
- **Настройки**: свой ретранслятор и обновления. Программа проверяет обновления на GitHub при запуске (это можно выключить) и ставит новую версию по кнопке, только если её контрольная сумма SHA-256 совпала с указанной на GitHub. Обновите программу на всех своих ПК: версии должны совпадать.

## Кодеки

Видео сжимается видеокартой. Если на подключающемся ПК есть аппаратный декодер H.265 (HEVC) и установлено бесплатное или купленное «Расширение для видео HEVC» из Microsoft Store, а на удалённом ПК есть кодировщик H.265, используется H.265: при том же битрейте картинка чётче, особенно через ретранслятор. Иначе используется H.264. Принудительно включить H.264 можно так: `rdesk.exe connect --h264 -- Название`.

## Что нужно учесть

- **Прокси и VPN в режиме TUN** (Clash, FlClash, v2rayN и подобные) пропускают трафик rdesk через свой сервер. Это добавляет задержку и мешает прямому соединению. Лучше добавить в их правила `rdesk.exe` как DIRECT, то есть в обход прокси.
- **Предупреждения Windows.** Файл не подписан, поэтому SmartScreen может показать предупреждение: нажмите «Подробнее», затем «Выполнить в любом случае». Брандмауэр при первом включении подключений попросит подтверждения: оно помогает прямым соединениям в локальной сети.
- **Windows N.** В редакциях N и KN нужен бесплатный Media Feature Pack от Microsoft: без него не работают ни видео, ни звук.

## Безопасность

- **Шифрование:** QUIC и TLS 1.3. ID устройства — это его открытый ключ Ed25519. При подключении проверяется, что на другой стороне именно владелец этого ключа, поэтому подменить удалённый ПК нельзя.
- **Доступ:** только для добавленных устройств. Чужие отключаются сразу после рукопожатия, до первого сообщения.
- **Добавление устройства:** одноразовый код из 8 цифр с протоколом SPAKE2, по записи трафика его не подобрать. Действует 2 минуты, допускается 3 попытки. Добавление открыто только пока показан код.
- **PIN при каждом подключении:** хранится только хэш PBKDF2. После 5 ошибок вход блокируется, время блокировки растёт до часа.
- **Подтверждение на месте:** если включить «Спрашивать разрешение на этом ПК при каждом подключении», после верного PIN на удалённом ПК появится вопрос: разрешить управление, разрешить только просмотр или отклонить. Без ответа за 30 секунд подключение отклоняется. Только просмотр соблюдается на стороне удалённого ПК: мышь и клавиатура подключившегося там игнорируются.
- **Ключи:** зашифрованы через DPAPI и привязаны к учётной записи Windows. Список устройств, PIN и настройка подтверждения подписаны, поэтому правка файла закрывает доступ всем.
- **Видимость:** во время сеанса на удалённом ПК поверх всех окон висит красный баннер с кнопками «Чат» и «Отключить».
- **Залипание клавиш:** при разрыве связи все клавиши и кнопки мыши отпускаются.

Если устройство потеряно, отзовите доступ в списке «Устройства с доступом сюда». Подробности событий находятся в `%APPDATA%\rdesk\rdesk.log`.

**Ограничения защиты:** вредоносная программа, запущенная под вашей учётной записью, обходит подписи и может перехватить PIN. Независимого аудита у программы не было.

## Ограничения

- Нет доступа к экрану блокировки и окнам UAC, сочетание `Ctrl+Alt+Del` передать нельзя: для этого нужна служба Windows, её пока нет.
- Звук идёт только с удалённого ПК, микрофон не передаётся.
- Через ретранслятор качество ниже. В тестах было 45–56 FPS при 8 Мбит/с и задержке около 200 мс.
- К одному ПК одновременно подключается одно устройство. С одного ПК можно подключаться к нескольким компьютерам сразу, каждый в своём окне.

## Сборка

Нужны Rust и Visual Studio с компонентами C++ и Windows SDK. Интерфейс сделан на [Slint](https://slint.dev) (стиль Fluent), описан в `ui/app.slint`.

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-light.svg)](https://slint.dev)

```bash
cargo build --release
```

```bash
cargo test -- --test-threads=1
```

Если проект лежит в очень глубокой папке, укажите короткий путь в `CARGO_TARGET_DIR`.
